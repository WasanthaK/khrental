## US-INV-01 — Save a tenant without sending an invitation

**As a** Tenant Administrator  
**I want** Save Tenant to persist a tenant without sending an invitation  
**So that** saving profile data and inviting an account remain separate actions.

### Preconditions

- Signed in as a Tenant Administrator.
- Use a new controlled test email.

### Steps

1. Create a tenant using **Save Tenant**, not Save & Invite.
2. Return to the Tenants directory.
3. Reload the page once.
4. Open the tenant details page.

### Expected

- Tenant remains visible after reload.
- Card and details show **Not Invited**.
- Action is **Send Invitation**.
- No invitation-created/expiry/accepted date is shown.
- No invitation email arrives.

### Evidence

**PASS — 2026-09-22.** Physical production acceptance confirmed plain Save Tenant persisted the renter as **Not Invited**, exposed **Send Invitation**, showed no invitation dates, and did not send an invitation email.

## US-INV-02 — Send the first invitation

**As a** Tenant Administrator  
**I want** to send an invitation to a saved tenant  
**So that** the tenant can securely claim the existing KH Rentals identity.

### Steps

1. Click **Send Invitation**.
2. Observe the persistent success/error message.
3. Observe the tenant card status.
4. Open tenant details.
5. Check the controlled mailbox, including Junk/Spam.

### Expected

- Success explicitly says the message was accepted by SendGrid for delivery.
- A provider reference is shown when SendGrid returns one.
- Status becomes **Invitation Pending**.
- Card shows **Invitation created** and **Expires**.
- Details page shows the same canonical status; it must not show **Unknown**.
- Button becomes **Resend Invitation**.
- Email arrives at the controlled mailbox.

### Evidence

**PASS — 2026-09-22.** The controlled production invitation reached SendGrid and the controlled mailbox (Junk), with explicit send feedback and the canonical pending lifecycle visible in production.

## US-INV-03 — Resend supersedes the previous invitation

**As a** Tenant Administrator  
**I want** resending to create a new single-use invitation  
**So that** earlier invitation links cannot remain valid indefinitely.

### Steps

1. Keep the first invitation email available without exposing its URL/token.
2. Click **Resend Invitation**.
3. Confirm a second invitation email arrives.
4. Use the first/older email link.
5. Use the newest email link.

### Expected

- Resend reports provider acceptance or a visible delivery error.
- Card remains **Invitation Pending** with the latest invitation dates.
- Older link reports that the invitation is unavailable/revoked/superseded and cannot create an account.
- Newest link opens **Complete Your Account Setup**.

### Evidence

**PASS — 2026-09-25, controlled `+102` flow.** Resend produced a new invitation; the older invitation was rejected as superseded/unavailable and the newest invitation remained usable for account setup.

## US-INV-04 — Accept invitation and create the account

**As an** invited tenant  
**I want** to complete account setup once  
**So that** the existing tenant identity becomes an authenticated KH Rentals account.

### Preconditions

- Use the newest valid invitation.
- Keep the Tenant Administrator page open in another tab/window if convenient.

### Steps

1. Open the newest invitation.
2. Complete account setup with a test password that meets requirements.
3. Confirm the invited account can sign in.
4. Return focus to the Tenant Administrator tab without manually re-sending anything.
5. Allow up to 30 seconds for the pending-state refresh, or switch away and back once.
6. Open tenant details.

### Expected

- Account setup succeeds once.
- Invited account can sign in normally.
- Tenant card changes from **Invitation Pending** to **Registered** automatically after focus/visibility refresh or within the pending polling interval.
- **Resend Invitation** disappears for the registered tenant.
- Card shows **Invitation accepted** with a date when available.
- Details page shows **Registered**, never **Unknown**.

### Evidence

**PASS — 2026-09-25, fresh account `+101`.** Invitation setup completed once, KH Rentals opened directly, the account entered the correct **Rentee** workspace, logout succeeded, normal login with the same created credential succeeded, and the Tenant Admin surface refreshed to **Registered**.

## US-INV-08 — Provider observability contains no sensitive invitation content

**As an** operator  
**I want** email delivery logs to be useful without exposing invitation content  
**So that** production troubleshooting does not leak credentials or one-time links.

### Steps

1. Correlate one controlled invitation using its request/provider reference where available.
2. Inspect the structured server email-delivery log entry.

### Expected

Allowed operational fields may include:

- timestamp
- component/event
- requestId
- provider
- providerStatus
- providerMessageId
- durationMs
- errorCode
- attachmentCount
- hasHtml / hasText

The logs must **not** contain:

- recipient email address
- email subject
- HTML/text email body
- invitation URL or invitation token
- reset token
- API key/secret
- password

### Evidence

**PENDING PHYSICAL LOG SPOT-CHECK.** The deployed implementation uses an allow-listed log record and automated tests prohibit recipient/subject/body/token/password/secret fields, but the final production log inspection required by this story is still outstanding.
